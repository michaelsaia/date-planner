## Decisions Made
- Separated pure scoring logic (`scoring.ts`) from DB-dependent suggestion service (`suggestions.ts`) so unit tests don't need database setup.
- Used a `DateIdeaInterest` join table rather than storing interest tags as strings on DateIdea — enables efficient SQL-based matching and maintains referential integrity.
- Scoring weights: 70% interest overlap, 30% budget fit. Budget score decays linearly outside the user's range rather than being a hard cutoff, so slightly over-budget ideas still appear.
- Seeded 20 date ideas covering all moods with 2–3 activities each, linked to existing interest categories. This provides enough variety for the suggestion engine without needing external API data.
