## Design Decisions
- **Semantic destructive colors over hardcoded red**: Added CSS variables so error states adapt to dark mode. Light mode uses standard red (#dc2626), dark mode uses a brighter red (#ef4444) with dark tinted backgrounds for proper contrast.
- **`bg-card` over `bg-white`**: The design system already defines `--card` for both themes. Using `bg-card` ensures filters and buttons look correct in dark mode without additional overrides.
- **`text-muted` over `text-foreground/80`**: The `--muted` color is purpose-built for secondary text. Using opacity modifiers on `foreground` creates inconsistent contrast across themes.
- **FilterBar h2 to span**: A text-sm element labeled "Filters" is not a document heading. Using `<span>` avoids polluting the heading hierarchy while preserving the visual styling.
- **Mood colors kept as hardcoded Tailwind colors**: Mood colors (pink, amber, sky, orange, green) are intentional per-mood theming, not generic UI colors. Creating CSS variables for each would add complexity without value since they're used in only two components.
