## Architecture Decisions
- **Toggle pattern**: Single POST endpoint that checks existing bookmark and creates/deletes accordingly. Returns `{ bookmarked: true/false }` so client always knows the final state.
- **Optimistic UI**: BookmarkButton immediately flips visual state, reverts on error. Prevents double-clicks with `pending` guard.
- **Parallel fetch**: SuggestionsFeed fetches bookmarked IDs in a separate useEffect (not blocking suggestions fetch). Merges state client-side.
- **Event propagation**: BookmarkButton uses `stopPropagation` + `preventDefault` to avoid triggering the parent Link navigation on cards.
