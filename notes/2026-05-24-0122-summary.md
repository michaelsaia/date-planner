## Architecture Decisions
- **In-memory library over DB table**: Surprises are small, static, and don't need CRUD. Keeping them in code avoids migration churn and makes them easy to maintain. If user-generated surprises are needed later, a DB table can be added.
- **Structured surprise object**: Changed from `string | null` to `{ text, category, id }` to support frontend features (display category labels, refresh by ID exclusion).
- **Mood-weighted selection**: Surprises are tagged with compatible moods rather than one-to-one mapping, allowing broader variety while maintaining relevance.
